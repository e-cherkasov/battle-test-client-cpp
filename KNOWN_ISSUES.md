# Известные проблемы и решения

1. Сейчас обхода занятых клеток нет. Юнит при движении идёт к цели по прямой и если следующая клетка занята - будет ждать. Тот, кто умеет бить, просто атакует соседа и клетка освобождается на следующем ходу после его смерти. А вот юнит с нулевым уроном упрётся и будет стоять. Если встанут все, то симуляция закончится с незавершённым ходом. Лекарю из планов (он не атакует) без обхода в 'Move' не обойтись.
2. Приоритет действий задаётся порядком 'addComponent'. Фабрики за счёт этого короткие, но действия неявные: если поставить 'Move' раньше атак то юнит молча пройдёт мимо врагов.
3. MARCH не проверяет, умеет ли юнит ходить. Юнит без 'Move (пр. Башня) напишет 'MARCH_STARTED' и так и останется на месте. Повторный Марш подменяет цель и 'MARCH_ENDED' для первой цели не будет.
4. Core сам создаёт события вывода: 'World' шлёт сообщения напрямую. Раз пока что формат лога фиксирован - это ок, но для другого вывода придётся лезть в Core.
5. Для части юнитов из плана нужны небольшие правки в Core:
   - Лекарь: у 'Health' нет 'heal' и максимального уровня здоровья.
   - Ворон: 'isAttackable' не знает ближняя атака или дальняя, а проверка охотника "рядом никого" посчитает ворона соседом.
   - Мина: 'Health' у неё нет, поэтому проверка "остался один юнит" считает её юнитом.

   Для Башни нового ничего не нужно добавлять по логике.
6. Спавн юнитов посреди раунда отсутствует. 'Simulation' итерируется по списку юнитов и 'World::addChild' во время раунда этот обход сломает. Для логики создания юнитов понадобится очередь, которую мир обработает в конце раунда. С удалением такой проблемы уже нет, я добавил 'Node::destroy()'.
7. Seed нельзя передать при запуске. 'main' каждый раз берёт случайный и не печатает его, чтобы не трогать формат вывода. Повторить битву пока можно только из кода или теста через 'Scenario::run(seed)'.
